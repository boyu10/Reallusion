主管三問專題剖析

「這個 Case 沒做，是時間不夠、API 沒開、還是根本不適合自動化？」

針對 Project 521 內部共 26 筆缺陷中，未獲選排入前十名自動回歸的代表性項目進行深入技術複盤。 對照官方最新 RLPy2 RD 規格書，闡明各 Case 背後的 3D 幾何斷言限制、C++ 接口缺失與工程投資回報率（ROI）取捨。

維度一 3 案例

● 根本不適合自動化

幾何破面、膚色人體美學、畫面著色器可見性。程式無例外崩潰，純屬人眼審美與主觀感受，自動化斷言極易產生大量誤報。

維度二 4 案例

● API 沒開 / 系統架構限制

查證 RLPy2 規格書確無接口。包括 3D Viewport 畫布滑鼠拖曳、3D Brush 封閉模組、渲染品質切換與進程銷毀崩潰。

維度三 3 案例

● 時間不夠 / ROI 不符

雲端 AI 伺服器非同步偶發 Race Condition、極度冗長的邊界分頁切換。衝刺期建置 Mock 成本巨大，手動點測 5 秒更具效益。

Mantis Project 521 | 幾何拓撲

#97447: [急診室 94] HS3 做的角色下嘴唇內部爛掉

根本不適合

步驟現象：生成角色後進入 Edit Facial 將 Jaw Open 調至最大值，下嘴唇內部出現網格撕裂爛掉（視覺破面）。

技術阻礙剖析： DirectX 渲染緩衝區接收均為合法座標，程式無例外。本質是拓撲平滑度與貼圖 UV 權重不足。圖像比對受抗鋸齒與光影干擾，誤報率極高。人工旋轉視圖 3 秒即可秒辨，寫法線偵測維護代價過大。
Mantis Project 521 | 膚色材質

#96881: 重複做 HS3 角色，角色頭和身體會膚色不一樣

根本不適合

步驟現象：在同一 Session 連續生成 HS3 角色，新角色的頭部與身體產生色差。

技術阻礙剖析： 頭身膚色的自然銜接度涉及人眼主觀審美判定。不同環境光照、PBR 著色器反射與貼圖色溫均會造成微幅數值漂移，以 RGB 絕對閥值斷言极易引發假警報。
Mantis Project 521 | 視圖渲染

#97978: Refine Face 存出再載入，Preview 出現 Front 且看不到 Mesh

根本不適合

步驟現象：Refine Face 先 Side 再 Front 存出角色後重新載入，開 Side 面板時 Preview 出現 Front 圖且看不到 Mesh。

技術阻礙剖析： 此為 3D 視圖著色器可見性（Visibility Shader）層級的視覺錯置，未發生底層崩潰。以自動化腳本驗證「模型是否能被肉眼看見」難以編寫客觀代數斷言，手動驗收最快。
Mantis Project 521 | 3D 畫布操作

#96538: Sculpt Morph 從 Viewport 左鍵 Drag, Morph 不會改變

API 沒開

步驟現象：開啟 Sculpt Morph 後，在 Viewport 3D 視圖中用滑鼠左鍵按住臉部頂點拖曳調整，Morph 完全無反應。

RLPy2 規格書查證： 規格書中完全沒有 Viewport.InjectMouseDrag() 或空間射線頂點拾取接口！滑鼠拖曳涉及螢幕至世界座標射線轉換（Unproject Ray）與筆刷衰減，Python API 層面根本觸碰不到。
Mantis Project 521 | 筆刷模組

#96928: Mesh Mode 生成的角色，開 3D Brush CC 會 crash

API 沒開

步驟現象：由 Mesh Mode 生成的角色，在後續流程嘗試開啟 3D Brush 工具時，Character Creator 發生崩潰。

RLPy2 規格書查證： 3D Brush 在 RLPy2 規格書中並未暴露任何筆刷圖層與點位注入接口（屬於內部封閉工具）。腳本無法在 API 層級操作 3D Brush 筆刷狀態。
Mantis Project 521 | 渲染管線

#97663: 開啟 Mask Brush Tool 後, Quality 切換 High 到 Medium 會 Crash

API 沒開

步驟現象：進入 Mask Brush Tool 繪製期間，點擊工具列將 Viewport Quality 從 High 切換為 Medium，CC 發生當機。

技術阻礙剖析： 涉及 Viewport Shader 即時重新編譯與 Mask 紋理記憶體交換。RLPy2 缺乏全域 Viewport 品質等級切換及管線重載回呼，無法以 Python API 模擬此動作。
Mantis Project 521 | 進程架構

#97569: CC4 & CC5 在有安裝 FashionGen 關閉AP 會產生 Crash Dump

架構限制

步驟現象：安裝 FashionGen 插件後，正常關閉 CC 主程式會在 Windows 系統產生 Crash Dump。

技術阻礙剖析： 崩潰發生於主程序 ExitProcess() 瞬間。此時 Python 直譯器已被強制卸載銷毀，腳本早就停止運行，內部 API 無法斷言。需靠 OS 層級腳本監控。
Mantis Project 521 | 雲端 AI 接口

#96765: Generate Character 面板按 AI Image Gen 鈕沒反應

時間/ROI

步驟現象：Project 521 中唯一明確標註 Auto Regression: None 的項目。點擊 AI Image Gen 鈕有時打得開、有時沒反應。

ROI 權衡剖析： 牽涉雲端 AI 伺服器通訊、Token 驗證與非同步彈窗。在 CI/CD 搭建 Mock AI Server 代價巨大，衝刺期戰力優先集中在核心頭部生成與微調當機，投入 5 天自動化此按鈕嚴重不符效益。
Mantis Project 521 | 非同步通訊

#97851: 從 Regenerate Character 面板開 AI Image Generator 沒反應

時間/ROI

步驟現象：點擊 Regenerate 面板後再開 AI Image Generator 無法開啟，其他入口正常。

ROI 權衡剖析： 多執行緒網路 Race Condition 與模態對話框鎖定。自動化測試在此類網路依賴環境極易產生假警報（Flakiness），維護成本遠高於手動點測。
Mantis Project 521 | 邊界切換

#96397: 切 Mesh Tab 載角色再切 Image Tab 資料消失

時間/ROI

步驟現象：HS3 切到 Mesh Tab，載入角色再切回 Image Tab，跳出 Overwrite 確認框點 OK 後圖片資料遺失。

ROI 權衡剖析： 極度罕見的操作路徑組合。手動驗證只需 5 秒鐘，自動化若要模擬彈窗確認與多標籤狀態切換需花費大量工時，生命週期總成本不具經濟效益。
